# Бетон — офлайн-калькулятор объёма заливки (PWA)

Мобильное приложение: рисуете контур плиты или ось ленты пальцем — приложение выпрямляет
углы до 90°, предлагает проставить реальные размеры и сразу считает кубометры бетона.
Без сервера, без интернета, все расчёты остаются в `localStorage` устройства.

```
npm i
npm run dev        # разработка
npm run build      # tsc --noEmit + vite build → dist/
npm run preview    # прод-сборка локально (на ней же гоняются e2e)
npm test           # юнит-тесты геометрии (vitest)
npm run e2e:all    # прогон интерфейса в headless Chromium (нужен запущенный preview)
```

## Поток

1. **Папка → Новый расчёт** → выбор типа: **Плита** или **Лента**. Расчёт создаётся только
   внутри папки; если папок ещё нет, главная предлагает создать первую.
2. Рисование по холсту (mouse/touch). Тап = точка; тап по первой точке замыкает контур.
   После трёх углов четвёртый достраивается сам. Жест двумя пальцами / колесо — зум,
   перетаскивание — панорама.
3. **Размеры.** Каждое введённое вручную число **закрепляется** (зелёное): пока это возможно,
   оно не меняется само, а новое значение поглощается свободными сторонами своей оси —
   предпочтительно одной, той, что лежит напротив изменяемой. Если одна из двух соседних
   перпендикулярных сторон закреплена, её край **остаётся на месте**, а сдвигается только
   противоположная; когда закреплены обе такие стороны или ни одной, изменение делится поровну.
   Зелёная длина не меняется сама: если свободных параллельных сторон не осталось, ввод
   отклоняется с подсказкой открепить одну из зелёных сторон. Вершины перерисовываются, углы
   остаются прямыми, контур замкнутым. **Долгое нажатие** на число закрепляет или освобождает
   сторону.
4. **Контур и толщина — параллельные вкладки**, а не шаги: переключаться можно в любой момент.
   У плиты — общая толщина и отдельные значения в вершинах (уклон), у ленты — общая глубина и
   отдельное значение для каждого отрезка. Объём виден всегда и
   пересчитывается на каждый ввод. Любое изменение сразу пишется в `localStorage`, выйти можно
   стрелкой «‹» и продолжить позже — вкладка и значения восстанавливаются.
5. **Несколько контуров.** На вкладке «Контур» есть «Добавить контур»: рисуете ещё один —
   снаружи плиты (объём прибавится) или внутри (станет выемкой). Роль не хранится, а
   вычисляется по вложенности: чётный уровень — бетон, нечётный — пустота, поэтому «остров»
   внутри выемки снова считается бетоном. Список контуров под кнопками показывает роль и
   площадь каждого, оттуда же его можно удалить. Сторону нужно держать с самого начала:
   начали снаружи — контур остаётся снаружи, начали внутри — остаётся внутри. Первый же
   отрезок, который пересёк границу уже нарисованного контура, не принимается, и подсказка
   появляется прямо во время рисования, а не только при замыкании. Как только контуров
   становится два, появляется
   вкладка **«Отступы»**: у вложенных контуров положение задаётся числами «слева / справа /
   сверху / снизу» от сторон родителя, у внешних добавочных — двумя или тремя реальными
   расстояниями до граней главного контура. Всё числами, без перетаскивания. Тап по числу
   отступа на холсте раскрывает нижнюю панель, прокручивает к его полю и подсвечивает его.
   В папке расчёт переименовывается, переносится в другую папку и удаляется через меню «⋯».

Лента устроена так же: холст сразу, две постоянные вкладки **Контур** и **Глубина**, никаких
шагов. Осевая линия может быть разомкнутой или кольцом. Отдельной кнопки ответвления нет:
тап по ленте и есть ответвление. Если линия ещё не начата, в месте тапа появляется узел на
оси и от него растёт новая ветка. Если линия уже ведётся, тап по ленте завершает её на оси —
последний отрезок только меняет длину, без лишнего угла. Тап по готовой вершине соединяет с
ней; тап по первой точке замыкает кольцо. Поэтому кольцо замыкается даже тогда, когда конец
оси не стоит на одной линии с началом. Замкнутое кольцо после замыкания ничем не
подсвечивается, и внутри него заливки нет — подсвечена только сама полоса. Лента может
пересекать себя: на перекрёстке две полосы просто накладываются, и объединение считает общий
квадрат один раз. Размеры ленты стоят не на оси, а на **видимых сторонах полосы**: у внешней и
внутренней стороны свои числа. Прямая стена, разбитая перегородками, с той стороны, где её
ничто не перерезает, остаётся одним размером; перегородка режет только ту сторону, в которую
упирается. Введённое число задаёт длину всей видимой стороны сразу — даже если она собрана из
нескольких отрезков, — и распределяется по ним; противоположная свободная сторона
подстраивается. Если напротив закреплена другая сторона, она сохраняет свою длину: когда
свободного параллельного участка нет, ввод отклоняется с предложением снять закрепление.
Закреплённая сторона подсвечивается зелёной линией по своей грани (долгое нажатие снимает
закрепление), а изменяемая выделяется пунктиром. Базовая ширина ленты — поле на вкладке «Контур», базовая глубина — на
«Глубине». Своя глубина участка: число у отрезка на вкладке «Глубина»; объём считается по
каждому ребру отдельно. Там же переключатель **Зуб отмостки**: утолщённый край идёт только по
внешнему контуру ленты — его наружная грань совпадает с лентой, а внутренняя отступает на
ширину зуба. По умолчанию 150 × 150 мм; глубина зуба прибавляется к объёму ленты, внутренние
перегородки и отверстия кольца зуб не получают. Своя ширина участка: тап по самой ленте открывает плашку «Ширина
участка» (там же «Всем»); участки с индивидуальной шириной помечаются
маленьким значком `↔`, чтобы не спорить за место с длинами. Выбранный отрезок удаляется кнопкой
«Удалить отрезок»: соседние линии сохраняют свои концы, а мостик просто исчезает. Тап по
вершине открывает плашку «Вершина» с удалением: точка на прямой исчезает без следа, угол —
вместе со своими отрезками, ответвление — вместе с точкой, а проходящая насквозь линия остаётся
целой. Висящих точек не остаётся никогда. Кнопка **Добавить линию** остаётся и после ввода
размеров: новые участки встраиваются в текущий масштаб, а введённые числа и закрепления
сохраняются.

## Расчёты и папки

Каждый расчёт получает имя: «Плита» или «Лента», а при совпадении — «Плита 2», «Лента 3» и
так далее. Имя меняется в шапке редактора тапом по названию (рядом карандаш) или через меню
«⋯» в папке; там же расчёт переносится в другую папку и удаляется с подтверждением.

Создавать расчёты можно только внутри папок. На главной — список папок с числом расчётов и
общим объёмом; тап открывает папку, где один блок «Новый расчёт» предлагает плиту или ленту,
а ниже лежит список расчётов. На пустой главной предлагается создать первую папку, и она
сразу открывается.

Папка переименовывается и удаляется из шапки своего экрана. Удаление папки удаляет и все
расчёты внутри — приложение показывает отдельное подтверждение с их числом. Перенос между
папками показывается в меню «⋯» расчёта, только когда есть куда переносить.

Имена и папки лежат в том же `localStorage`, поэтому переживают перезапуск: старые сохранения
без имени получают понятное имя при чтении, а расчёты, лежавшие вне папок, попадают в папку
«Мои расчёты».

## Как работает геометрия

### Плита — `fitOrthogonalPolygon` (`src/geometry/ortho.ts`)

1. Каждое ребро эскиза классифицируется как горизонтальное или вертикальное.
2. Узлы, обязанные иметь общий `x` (вертикальные рёбра) или общий `y` (горизонтальные),
   сливаются взвешенным union-find: вес узла = сумма длин примыкающих рёбер, поэтому
   сдвиг распределяется «по длине», как ожидает человек.
3. Если в одной оси замыкается цикл — такой ортогональный контур невозможен, операция
   отклоняется с понятным сообщением. Если после слияния ребро стало нулевым или
   наклонным (конфликт) — тоже отказ.
4. Проверка простоты (без самопересечений) и ≥ 4 точек.

Объём плиты: каждый контур триангулируется на полосы; для каждой полосы толщина
интерполируется линейно между толщинами вершин, интеграл даёт `volumeMm3`
(`src/geometry/slab.ts`). Объёмы складываются со знаком: контуры чётного уровня вложенности
прибавляются, нечётного — вычитаются. Площадь в HUD — тоже чистая (минус выемки).
Как только введён первый размер, рядом с объёмом появляется компактный бейдж габаритов
активной сцены: ширина × высота полезной площади в метрах.

### Лента — `fitNetwork` + `buildStrip` (`src/geometry/strip.ts`)

* Сеть узлов/рёбер выпрямляется тем же union-find (x для вертикальных, y для горизонтальных),
  затем валидируется топология: нулевые рёбра и недостающие узлы → отказ с текстом ошибки.
  Пересечение осей без общего узла разрешено — это перекрёсток; полосы объединяются,
  поэтому площадь и объём в месте пересечения учитываются один раз, а не дважды.
  Наложение отрезков вдоль одной линии тоже допустимо: общая полоса входит в объём один раз,
  а сами оси сливаются в одну линию. Концы наложения становятся обычными вершинами — от них
  можно сразу строить ответвление, и пунктир рисуется один раз.
* Автоматическое соединение: при тапе по вершине или ребру `orthogonalConnector` подбирает
  недостающий угол так, чтобы новый участок не пошёл обратно поверх уже нарисованного;
  ребро при необходимости разбивается узлом с сохранением своей ширины.
* Каждое ребро — прямоугольник шириной участка, продлённый на половину ширины в
  перпендикулярных стыках, чтобы угол/T-стык сомкнулся без щелей.
* Объединение прямоугольников считается точно через сжатие координат
  (`src/geometry/union.ts`): площадь, объём (высота интерполируется вдоль оси ребра) и
  контур для отрисовки. Обход границы идёт «по самому правому повороту», поэтому
  T-образные стыки не рвут контур на диагонали.
* Размеры берутся с готового контура объединения (`faceRuns`): одна метка на каждую
  непрерывную видимую грань. Коллинеарные грани объединение уже склеивает, поэтому стена,
  которую перегородка только касается изнутри, снаружи остаётся одним размером, а с
  внутренней стороны делится по месту стыка. Торцы в размеры не попадают. Ключ закрепления
  строится из отрезков-опор, стороны и порядка грани, поэтому закрепление переживает
  изменение длин и разбиение стены. Смещение метки — по правой нормали ребра контура: у
  внешнего контура она смотрит наружу, у отверстия — в пустоту. Сторона стыка считается с
  учётом направления соседнего отрезка, поэтому разворот отрезка при рисовании не меняет,
  где внешняя, а где внутренняя сторона.

### Несколько контуров (`deriveSlab` / `closeSlabContour` в `src/state/derive.ts`)

Плита хранит массив `contours`, у каждого — свой эскиз, выпрямленный контур, длины и
закрепления. Роль контура выводится из геометрии: `nestingDepth` проверяет, внутри скольких
других контуров лежит внутренняя точка этого (`interiorPoint` + `pointInPolygon`), и чётность
даёт «прибавляется» или «вычитается». Внутренняя точка берётся вместо вершины или центроида:
при нулевом отступе контуры могут касаться, а вершина окажется на чужом ребре; центр тоже
может попасть на ребро соседа.

При замыкании нового контура `closeSlabContour` выпрямляет его и проверяет каждое ребро
против каждого ребра уже принятых (`contoursProperlyCross`). Реальное пересечение — отказ с
текстом «контуры пересекаются», а касание или общая граница допустимы: это обычное
примыкание при нулевом отступе. Поэтому неоднозначных случаев «наполовину внутри» не бывает.
Первый введённый размер переводит в миллиметры **все** контуры сразу (общий `k` и общий
сдвиг), чтобы их взаимное расположение сохранилось.

Отсюда же ограничение на правку длины: варианты пересчёта перебираются до первого, который
остаётся простым и не налезает на соседний контур. Если контуры вплотную и расти некуда —
ввод отклоняется с подсказкой открепить мешающую сторону.

### Отступы контуров (`slabPlacements` / `setSlabContourOffset` в `src/state/derive.ts`)

Когда замкнутых контуров больше одного, появляется третья вкладка **«Отступы»** — точное
позиционирование вместо перетаскивания. У вложенных контуров (выемок и островов внутри них)
показываются четыре числа: `слева`, `справа`, `сверху` и `снизу` в миллиметрах от
соответствующих сторон контура-родителя. Родитель — самый внутренний контур, который его
охватывает (у выемки это плита, у острова — выемка). Размер контура при этом не меняется,
поэтому после правки одной стороны противоположная пересчитывается автоматически:
`right = ширина родителя − ширина контура − left` (аналогично сверху/снизу).

Внешний добавочный контур лежит снаружи главного, и отступы «от четырёх сторон» дали бы
отрицательные числа, как только он оказался бы справа или снизу. Вместо них показываются
только **реальные расстояния** до главного контура:

- контур сбоку или сверху/снизу — три числа: зазор между обращёнными гранями и расстояния
  между параллельными гранями по другой оси (сверху и снизу либо слева и справа);
- контур по диагонали — два числа: `зазор X` и `зазор Y` между ближайшими гранями.

Отрицательных значений не бывает, а `0` разрешён и означает, что контур вплотную примыкает
к грани главного (или к границе родителя у выемки). Такое примыкание не считается
наложением: проверяется только реальное пересечение контуров, а общая граница допустима.
Правка зазора сохраняет текущую сторону — контур не перескакивает через главный. У
трёхчислового варианта правка верхнего/нижнего (или левого/правого) расстояния сдвигает
контур вдоль этой оси, а второе расстояние пересчитывается само, потому что размер контура
не меняется.

Правка отступа не трогает ни одной длины: контур сдвигается целиком — меняется `pivot`
(полигон строится вокруг него из `lens`), поэтому все углы остаются 90°, а закрепления и
толщины вершин сохраняются. Перед сохранением проверяется `isSimplePolygon`, отсутствие
реального пересечения с соседями (`contoursProperlyCross`; общая граница при нулевом
отступе допустима) и неизменность вложенности: выемка не может выехать из плиты, а внешний
контур — оказаться внутри чужого. При нарушении ввод отклоняется тостом,
а число возвращается к прежнему значению. На холсте у вложенных контуров отступы показаны
зелёными размерными линиями со всех четырёх сторон, у внешних — двумя или тремя линиями
реальных расстояний до главного; при тесных зазорах подпись скрывается, чтобы не перекрывать
номера сторон.

### Длины и закрепление (`contourPoly` / `setSlabEdgeLength` / `solveSlabLens` в `src/state/derive.ts`)

Углы выпрямлены один раз (`fitOrthogonalPolygon`), он же даёт направление каждого ребра
(ось + знак). Дальше хранятся **реальные длины рёбер** `lens[]`, а контур строится обходом:
`p[i+1] = p[i] + dir[i] * len[i]`. Поэтому 90° выполняются по построению, а любое число
можно править независимо.

`pinned[]` — рёбра, чьи числа ввёл человек. Они никогда не пересчитываются: ввод только
добавляет ребро в набор. Замкнутый ортогональный контур требует `Σ ±len = 0` по каждой оси,
поэтому решатель (`solveSlabLens`) на каждой оси оставляет закреплённые длины как есть, а
недостачу относит на **свободные** рёбра. Порядок предпочтения:

1. одна свободная сторона, в первую очередь противолежащая изменяемой (противоположный знак,
   максимальное удаление по перпендикуляру) — тогда сдвигается целиком именно она, а не всё
   сразу. Если одна из двух соседних перпендикулярных сторон закреплена, её линия остаётся на
   месте: `polyFromLens` получает `anchor` и не перецентровывает контур по этой оси, поэтому вся
   разница уходит на противоположную сторону. При двух закреплённых или двух свободных соседях
   якоря нет и сдвиг делится поровну, как раньше;
2. если она выходит за допуск 10 мм … 200 м — разница делится поровну между свободными;
3. если и это невозможно — пропорциональный масштаб `k = R / Σ±len(free)`.

`setSlabEdgeLength` перебирает варианты по порядку и берёт первый, у которого контур простой и
ненулевой (`isSimplePolygon`), поэтому «0 мм» на редактируемом выступе больше не мешает
сдвинуть противолежащую сторону. Если свободных рёбер на оси нет, или ни один вариант не
проходит, ввод отвергается с сообщением «закреплённые стороны не сходятся — открепите одну»,
состояние не меняется. Долгое нажатие только меняет набор `pinned[]`: длины при этом не
трогаются, геометрия остаётся валидной.

Старые расчёты (одиночный контур, `sx/sy`, `refEdge`) поднимаются в `contours[]` при чтении
(`migrateSlab` в `src/state/types.ts`), `refEdge` превращается в `pinned[]` (`pinnedEdges`),
а длины первого контура читаются через `contourLens`.

### Длины ленты (`stripLens` / `stripNodesFromLens` / `setStripSegLength` в `src/state/derive.ts`)

Сеть ленты тоже хранит **реальные длины участков** `lens` в миллиметрах и набор `pinned`.
Геометрия восстанавливается из них: для каждой оси участок даёт разность координат
(`x_b − x_a = ±len`), а перпендикулярный — равенство (`x_b = x_a`), поэтому один обход в
ширину расставляет все узлы, а углы 90° получаются по построению. Первое введённое число
просто переводит эскиз в миллиметры (равномерный `k`), дальше каждое число закрепляется.

Замкнутое кольцо требует, чтобы вдоль каждого независимого цикла сумма знаковых длин по
каждой оси была нулевой. Решатель `solveStripLens` строит фундаментальные циклы (дерево +
замыкающие рёбра), считает невязку и отдаёт её **свободному** участку той же оси внутри
цикла — сначала тому, что лежит напротив изменяемого, затем любому. И `pinned`, и зелёные
стороны граней (`sidePins`) — жёсткие ограничения: их длины не меняются, пока пользователь сам
не открепит сторону. Если свободных параллельных участков в цикле не осталось, решатель
возвращает конфликт, и интерфейс просит снять закрепление с параллельной зелёной стороны.
Разомкнутая ось циклов не имеет, поэтому любой размер там просто задаётся; после подбора длины
проверяются топологией (`validateTopology`) и сборкой узлов, поэтому невозможная геометрия не
сохраняется.

Позиция зелёных сторон тоже сохраняется: `stripNodesFromLens` центрирует компонент по эскизу,
поэтому после пересчёта длин `anchorStripNodes` сдвигает `baseNodes` так, чтобы линии
закреплённых граней остались на месте. Одна закреплённая перпендикулярная сторона — стоит, а
сдвигается свободная; две — их запросы усредняются, и обе стороны расходятся поровну. Сдвиг
хранится в `baseNodes`, так что переживает перезагрузку и следующие правки.

## UX-решения, которые стоит знать

* Холст не «перепрыгивает» при вводе: вьюпорт меняется только при первом размере (когда
  эскиз превращается в миллиметры), переключение вкладок масштаб не трогает.
* На телефоне нижняя панель занимает не больше трети экрана и прокручивается отдельно;
  круглая кнопка в одной строке с вкладками сворачивает её до этих вкладок, отдавая холсту
  почти весь экран.
* Опасные действия — «Очистить холст», удаление расчёта или папки — подтверждаются
  встроенным диалогом в стиле приложения, а не системным окном браузера.
* «Добавить контур» слегка отдаляет холст, чтобы вокруг плиты было куда рисовать; плашки
  размеров на время рисования скрываются — иначе они перехватывают тапы по холсту.
* Числовые плашки разводятся друг от друга, но не прижимаются к краю холста: подпись
  остаётся у своей стороны и уходит вместе с ней за экран — и у плиты, и у ленты.
* Ошибочные формы не «портят» чертёж: сначала считается геометрия, и только при успехе
  точка/отрезок попадают в состояние; иначе — вибро + текстовый алерт.
* Ширина участка открывается тапом по самой ленте, а не отдельными числами у каждого
  участка: на экране 390 px иначе 12+ подписей спорят за место.

## Офлайн

`public/sw.js` кеширует шелл и все запросы (cache-first, навигация — network-first с
fallback в кеш), `manifest.webmanifest` даёт установку на домашний экран. Данные —
только `localStorage`, никаких сетевых вызовов в приложении нет.

## Ограничения

* Ортогональность принудительная: косые стены не поддерживаются (это осознанно).
* Контуры плиты либо не пересекаются вовсе, либо один целиком внутри другого. Общая
  граница допустима (нулевой отступ), а частичное наложение отклоняется. Вплотную
  приставленные друг к другу плиты считаются двумя объёмами — для Г-образной формы
  рисуйте один контур.
* Лента может пересекать сама себя: пересечение осей без общего узла — это перекрёсток,
  а не ошибка. Две полосы объединяются, поэтому общий квадрат входит в площадь и объём
  один раз. Отрезок, проложенный поверх другого вдоль той же линии, тоже не ошибка —
  наложение считается один раз.
* Объём ленты считается по призматической модели: высота постоянна в пределах отрезка и
  задаётся для каждого ребра отдельно, без учёта опалубки и перерасхода.
